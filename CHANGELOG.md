## [0.3.1-beta] - 2026-11-26

This hotfix updates easycorp/easyadmin-bundle from 5.10.2 to 5.10.4 (and doctrine/collections from 3.1.0 to 3.1.1 as its dependency). EasyAdmin published eight security advisories on 2026-11-25 for the admin backend: file and image fields that skip upload restrictions or look up files outside the upload directory, autocomplete, search and sort that use fields or pages the user cannot access, crafted links that change what delete buttons and boolean switches act on, route parameters passed as controller arguments, a bypass of forced downloads, and permissions on form tabs, columns and fieldsets that only hid the heading. The admin backend is reachable by administrators only.

Existing installations: no extra steps, see the [upgrade guide](docs/05-operations/upgrading.md#v03-beta--v031-beta). Installations still on v0.2.x follow the v0.3-beta section and deploy v0.3.1-beta directly.

## [0.3-beta] - 2026-11-26

This third beta makes the platform feature complete for 1.0. It brings a second kind of clinical data in an encounter data pilot: hospitals prepare their emergency department export with an offline data preparation tool, pseudonymise it and upload ED visits with their Manchester Triage System assessment, which a matcher links to IVENA allocations for review, validation and descriptive statistics. ED visits ship as the first schema plugin. Closure Analytics and closure imports leave the beta.

Participation follows clearer rules: the acceptance of the terms of use is stored with its version, uploaders confirm once per hospital that they may upload its data, and Explore shows individual allocations only for the viewer's own hospitals. Research projects can request data extracts with a Board vote, admin-written queries on a read-only connection and a time-limited download. Statistics require at least three hospitals per scope, follow the adult age threshold and label percentage-point changes. Navigation was rebuilt around one tree with sidebars, a Tools section, a searchable help section with glossary and data catalog, and a print layout. Users sign in with username or email, optionally with a login link; two-factor authentication is available and required for administrators.

For operators, the audit log became a timeline, suspicious feedback goes into a quarantine, the page editor saves drafts, usage analytics was reduced to counted accesses, media files moved into a managed storage with integrity checks, dispatch-area geography became maintained master data, backups run weekly with verification and an off-site copy, and a maintenance mode keeps users out while an upgrade finishes.

A pre-release security review closed missing escaping in admin views, gaps in the sign-in checks and weak points of the data extract checks; remembered users sign in once more after the upgrade.

Existing installations: the release has 59 migrations, one-time commands and new configuration; follow the [upgrade guide](docs/05-operations/upgrading.md#v027-beta--v03-beta).

## [0.2.7-beta] - 2026-11-26

This hotfix updates the Symfony components from 8.1.9–8.1.11 to 8.1.12. Symfony published 19 security advisories on 2026-11-25 for eleven of the components this application uses. Among them: login redirects and generated URLs that could still reach another host, a way around `require_tls` in the mailer, `access_control` rules granted by the unanimous strategy when only one of their attributes passes, HTML sanitizer, HTTP client and serializer issues, and remember-me tokens accepted after they were outdated. All 8.1 components move to 8.1.12 together.

The security policy now says what was already practised: only the newest patch version of the latest beta receives fixes; v0.1-beta is no longer supported.

Existing installations: no extra steps, see the [upgrade guide](docs/05-operations/upgrading.md#v026-beta--v027-beta).

## [0.2.6-beta] - 2026-11-24

This hotfix updates twig/twig from 3.30.0 and twig/html-extra from 3.31.0 to 3.31.1. Twig published ten security advisories on 2026-11-23 and 2026-11-24. Nine are ways around the Twig sandbox, including one through `html_cva()` in twig/html-extra; the application uses neither the sandbox nor `html_cva()`. The tenth fixes missing autoescaping for a variable that is named like a macro import alias of another scope.

## [0.2-beta] - 2026-10-31

This second beta completes the foundation of the collaborative IVENA statistics platform. On top of the allocation statistics of v0.1-beta it adds a second data source: IVENA closure lists are imported and analysed as closure analytics with profiles, volume projections and constellations, and closed-department metrics reach the monthly reports. Statistics gain Insights across catalog dimensions, a guided analysis assistant, Top List exports and comparisons, and maps for allocation orientation, isochrone origins and dispatch area catchments.

Operations got a monitoring baseline: storage monitoring with capacity alerts, run summaries and alerts for background jobs, Messenger monitoring, and a multi-channel notification system. Imports can be reprocessed, handled in bulk and show their data coverage. The reference catalog is now portable, so the repository holds no curated data, and a synthetic data generator with an offline demo environment makes the platform presentable without real hospital data. Under the hood the UI was consolidated into shared components (DataTable, filters, modals, mobile cards), all code reads time from the Symfony clock, a pre-release security audit and consistency review tightened access checks and removed dead code, and CI, tests and agent instructions were tightened.

Existing installations: follow the [upgrade guide](docs/05-operations/upgrading.md#v01-beta--v02-beta) for configuration changes and one-time commands after the deploy.
